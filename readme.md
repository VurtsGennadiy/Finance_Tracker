# Wallet Control — трекер личных финансов

Приложение для учёта личных финансов: все счета, карты и займы в одном месте. Позволяет
фиксировать доходы и расходы, переводить средства между счетами, контролировать долги
и анализировать историю операций по категориям, периодам и счетам.

## Возможности

### Пользователи и доступ
- Регистрация и вход через форму (Spring Security).
- Подтверждение email по ссылке из письма, повторная отправка ссылки.
- Просроченные токены подтверждения email периодически удаляются планировщиком.
- Все операции со счетами доступны только их владельцу: право собственности проверяется
  в сервисном слое, а не только скрытыми полями форм.

### Счета
- Пять типов счетов: наличные, банковский счёт, дебетовая карта, кредитная карта, займ.
- Создание и удаление счёта; для карт и банковского счёта — банк, номер карты/счёта.
- Начальный баланс счёта при ненулевом значении фиксируется отдельной транзакцией.
- Группировка счетов по типам на главной странице.
- Изменение кредитного лимита для кредитной карты: лимит может быть увеличен, уменьшен
  или сброшен в `0`, но не может быть отрицательным. Баланс счёта компенсируется на величину
  разницы лимитов, в историю добавляется транзакция `CREDIT_LIMIT_CHANGE`.

### Операции
- Доход и расход с категорией, датой и комментарием.
- Перевод между счетами: создаются две связанные транзакции (списание и пополнение).
- Отмена операции с автоматическим пересчётом баланса счёта; отмена перевода откатывает
  обе связанные транзакции. Начальный баланс и изменение кредитного лимита отменить нельзя.
- История операций: фильтры по периоду (7/30 дней или произвольный), по счетам, показ
  переводов, пагинация, сводка доходов и расходов за период.
- Последние операции на главной странице и на странице счёта.

### Главная страница
- Доступные средства, общий баланс, сумма долгов и сумма, которую должны пользователю.
- Быстрые действия «Доход», «Расход», «Перевод».
- Счета, сгруппированные по типам, с текущим балансом.
- Предупреждение о неподтверждённом email и подсказка при отсутствии счетов.

## Архитектура

Приложение — монолит на Spring Boot с серверным рендерингом страниц Thymeleaf.
Разделение по слоям:

```
web / facade → service → dal
```

| Слой | Назначение |
|---|---|
| `web` | MVC-контроллеры: приём форм, валидация, flash-сообщения, выбор шаблона |
| `facade` | Сборка данных для страниц (главная, история операций) из нескольких сервисов |
| `service` | Бизнес-логика, проверка прав, транзакции (`@Transactional`), DTO |
| `dal` | JPA-сущности и Spring Data JPA репозитории |
| `util/mapper` | MapStruct-мапперы между сущностями и DTO |
| `security` | `SecurityUser`, `JpaUserDetailsService`, конфигурация Spring Security |
| `dev` | Dev-профиль: автоаутентификация, `DataSeeder` с демо-данными |

Ключевые принципы:
- контроллеры не работают с репозиториями напрямую, наружу отдаются DTO, а не JPA-сущности;
- денежные суммы — только `BigDecimal` с масштабом 2;
- идентификаторы — `UUID` (в PostgreSQL — `uuidv7()` по умолчанию);
- баланс счёта равен сумме его транзакций: доход и входящий перевод увеличивают баланс,
  расход и исходящий перевод уменьшают, изменение кредитного лимита записывается
  знаковой дельтой;
- схема БД управляется только Liquibase (`ddl-auto: none`), изменения — новыми
  changeset'ами в `db/changelog/v.0.0.N/`.

### Структура проекта

```
src/main/java/ru/vgd/tracker/
├── web/              контроллеры (главная, счета, транзакции, auth, ошибки)
├── facade/           данные для страниц (главная, история операций)
├── service/          интерфейсы, impl/ и dto/
├── dal/              entity и repository: user, account, transaction, token
├── security/         Spring Security
├── config/           AsyncConfig, SchedulerConfig
├── util/mapper/      MapStruct-мапперы
├── exception/        доменные исключения
└── dev/              dev-профиль (DevSecurityConfig, DataSeeder)

src/main/resources/
├── db/changelog/     миграции Liquibase (только добавление новых файлов)
├── templates/        Thymeleaf-шаблоны и layout
├── static/           css, js, favicon
└── application*.yaml конфигурация профилей
```

### Профили

- `dev` — локальная БД `wallet_dev`, подробные логи, автоаутентификация и демо-данные
  (пользователи `admin` и `user`).
- `prod` — параметры подключения и секреты через переменные окружения, подробные ошибки
  пользователю не показываются.
- Базовый профиль (`application.yaml`) — общие настройки приложения.

## Запуск

Требования: JDK 21, Docker, PostgreSQL (поднимается через `docker compose`).

1. Задайте переменные окружения (см. `docker-compose.yaml`): `POSTGRES_DB`, `POSTGRES_USER`,
   `POSTGRES_PASSWORD`, `DB_URL`, `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `MAIL_USERNAME`,
   `MAIL_PASSWORD`. Для `docker compose` они читаются из `.env`; при локальном запуске через
   Maven задайте их в оболочке или в конфигурации IDE. Секреты в репозиторий не коммитятся.

2. Поднимите базу данных:

   ```powershell
   docker compose up -d db
   ```

3. Запустите приложение в dev-профиле:

   ```powershell
   .\mvnw.cmd spring-boot:run "-Dspring-boot.run.profiles=dev"
   ```

   Приложение будет доступно по адресу http://localhost:8080. В dev-профиле выполняется
   автоматический вход и создаются демонстрационные счета.

4. Полный запуск в Docker (prod-профиль):

   ```powershell
   docker compose up -d --build
   ```
